## Brooks ICS

The Brooks ICS is a command-line tool for using the features of the [Brooks implementation](https://github.com/cerfcast/brooks) of the ["metadata expression language" (MEL)](https://datatracker.ietf.org/doc/draft-ietf-cdni-metadata-expression-language/) and ["processing stages"](https://datatracker.ietf.org/doc/draft-ietf-cdni-processing-stages-metadata/) specifications being developed by the [CDNI working group](https://datatracker.ietf.org/group/cdni/about/) at the IETF to provide interconnection server-related functionality.

In particular, Brooks ICS provides tools to help a CDN communicate with downstream/upstream CDNs and maintain a
queryable interface of [metadata objects](https://www.rfc-editor.org/rfc/rfc8006.html#section-4) specific to hosts/paths.
In particular, the ICS tools allow a CDN to run a server that will accept metadata objects from upstream CDNs and respond to queries to fetch
metadata objects specific to a host or a path (for processing to respond to a user request).[^more]

[^more]: For more about how the "Content Delivery Network Interconnection (CDNI) Metadata interface enables
interconnected Content Delivery Networks (CDNs) to exchange content distribution metadata in order to enable content
acquisition and delivery," see [RFC8006](https://www.rfc-editor.org/rfc/rfc8006.html).

### Demo Running

There is a demonstration of the Brooks ICS + [Brooks library integrations](https://github.com/cerfcast/brooks#integrations) running
online at [mel.cerfca.st]. To explore, there are a few premade HTTP requests designed to simulate how the system would work
for an end user requesting content from a CDN participating in CDNI:

#### Scenario 1: User Requests Connection To cnn.com -> Upstream CDN Delivers example.com

In this scenario, the user requests content from cnn.com and the upstream CDN delivers content from example.com. In the process of sending the origin request
to the uCDN, the request is modified. In the process of sending the uCDN's response to the user, the response is modified.

To see it in action, use [https://hopp.sh/r/k8trzWMB4ACt](https://hopp.sh/r/k8trzWMB4ACt).

#### Scenario 2: User Requests Connection To example.com -> Upstream CDN Delivers cnn.com

In this scenario, the user requests content from example.com and the upstream CDN delivers content from cnn.com. In the process of sending the origin request
to the uCDN, the request is modified. In the process of sending the uCDN's response to the user, the response is modified.

To see it in action, use [https://hopp.sh/r/hDJpwbSaknoX](https://hopp.sh/r/hDJpwbSaknoX).

#### Scenario 3: User Requests Connection To gmail.com And Gets Synthetic Response

In this scenario, the user requests content from gmail.com and CDN delivers a simple synthetic response generated by the evaluation of a
[MEL expression](https://datatracker.ietf.org/doc/draft-ietf-cdni-metadata-expression-language/).

To see it in action, use [https://hopp.sh/r/LR58SZXzhuEJ](https://hopp.sh/r/LR58SZXzhuEJ).
